# 프로젝트 구조 상세 설명

식품(과자/베이커리) 키워드의 바이럴 강도를 예측하는 ML 파이프라인

---

## 전체 구조

```
capstone-ml/
│
├── configs/                    # 설정값 중앙 관리 (YAML)
│   └── collection.yaml         #   수집 파이프라인 설정
│
├── pipeline/                   # 모든 실행 코드
│   ├── collection/             #   Stage 1: 데이터 수집
│   ├── preprocessing/          #   Stage 2: 전처리
│   ├── features/               #   Stage 3: 피처·타겟 생성
│   ├── training/               #   Stage 4: 학습·평가
│   └── inference/              #   추론 (학습과 별개 흐름)
│
├── data/                       # 모든 데이터 (.gitignore)
│   ├── raw/                    #   수집 원본 (불변)
│   ├── interim/                #   전처리 중간 산출물
│   └── processed/              #   학습 준비 완료 데이터
│
├── outputs/                    # 실험 결과 (.gitignore)
│   ├── models/                 #   저장된 weight
│   ├── metrics/                #   평가 결과
│   └── figures/                #   SHAP plot, 차트
│
├── experiments/                # 탐색적 실험 (파이프라인 외)
├── notebooks/                  # EDA 전용 (프로덕션 코드 금지)
├── docs/                       # 설계 문서
├── tests/                      # 단위 테스트 (pytest)
│
├── requirements.txt
├── .env                        # API 키 (git 제외)
├── .gitignore
└── README.md
```

---

## 설계 원칙

핵심 원칙 3가지:
1. **코드와 데이터 분리** — `pipeline/`(코드)과 `data/`(데이터)를 최상위에서 나눈다
2. **스테이지 독립성** — 각 파이프라인 스테이지는 `data/`의 파일을 통해서만 연결된다
3. **설정과 로직 분리** — 하드코딩 대신 `configs/`의 YAML로 설정을 관리한다

---

## pipeline/ — 파이프라인 스테이지

### 데이터 흐름

```
collection/    → 읽기: configs/, .env       → 쓰기: data/raw/
preprocessing/ → 읽기: data/raw/            → 쓰기: data/interim/
features/      → 읽기: data/interim/        → 쓰기: data/processed/
training/      → 읽기: data/processed/      → 쓰기: outputs/
inference/     → 읽기: data/processed/, outputs/models/  → 쓰기: outputs/
```

각 스테이지가 독립적인 entry point 역할을 하므로, 특정 스테이지에서 문제가 생기면 그 스테이지만 재실행

### collection/ — Stage 1: 데이터 수집

| 파일 | 역할 |
|------|------|
| `crawl_keywords.py` | 네이버 데이터랩 쇼핑인사이트에서 월별 키워드 Top 500 크롤링 + 윈도우별 CSV 검증·통합 |
| `select_keywords.py` | 통합 CSV에서 appearance 사분위 계층 샘플링으로 500개 키워드 선정 |
| `crawl_shopping_click_trend.py` | 선정 키워드의 일별 쇼핑 클릭 트렌드 수집 (오픈API) |
| `crawl_search_trend.py` | 선정 키워드의 일별 통합 검색 트렌드 수집 (오픈API) |
| `crawl_shopping_click_gender.py` | 선정 키워드의 일별 성별 쇼핑 클릭 트렌드 수집 (오픈API) |
| `crawl_shopping_click_age.py` | 선정 키워드의 일별 연령별 쇼핑 클릭 트렌드 수집 (오픈API) |
| `derive_gender_proportion.py` | 성별 ratio → 남/여 비율(%) 산출 |
| `derive_age_proportion.py` | 연령별 ratio → 연령대 비율(%) 산출 |
| `ratio_to_absolute.py` | ratio ↔ absolute 변환 공유 모듈 |
| `estimate_shopping_click_absolute.py` | 쇼핑 클릭 트렌드 ratio → 절대값 역산 |
| `estimate_search_absolute.py` | 통합 검색 트렌드 ratio → 절대값 역산 |
| `verify_shopping_click_absolute.py` | 쇼핑 클릭 절대값 검증 (round-trip) |
| `verify_search_absolute.py` | 검색 절대값 검증 (round-trip, 배치 교차, 앵커) |


### preprocessing/ — Stage 2: 전처리

수집된 원본 데이터의 소스 조인, 결측치 처리를 수행할 예정.

### features/ — Stage 3: 피처 생성

| 파일 | 역할 |
|------|------|
| `build_dataset_final.py` | Phase 1+2+3 51개 피처 + 레이블 생성 → `data/processed/dataset_final.csv` 출력 |
| `build_dataset.py` | Phase 1 전용 (24개 피처) 레거시 스크립트 |

### training/ — Stage 4: 학습·평가

모델 학습과 평가를 수행할 예정.

### inference/ — 추론

학습된 모델로 새 키워드의 바이럴 강도를 예측할 예정.

## data/ — 데이터 3단계

Git에서 제외되며(`.gitignore`), `.gitkeep`으로 폴더 구조만 유지한다.

| 단계 | 원칙 | 이 프로젝트에서 |
|------|------|----------------|
| `raw/` | **불변**. 수집한 그대로 보존 | 검색·클릭 절댓값/ratio, 성별·연령 클릭 비율, SomeTrend 언급량 (21개 CSV) |
| `interim/` | 소스 조인 + 결측치 처리 완료. 아직 피처 아님 | (keyword, date, search_trend, ...) 형태의 통합 테이블 |
| `processed/` | 모델에 바로 넣을 수 있는 최종 형태 | `dataset_final.csv` — 573,285샘플 × 51피처 (LightGBM 즉시 학습 가능) |

### raw/

```
data/raw/                                    # 모든 파일 flat 구조 (서브폴더 없음)
├── search_absolute.csv                      # 통합 검색량 절댓값 (wide: 500키워드 × 1,420일)
├── search_trend.csv                         # 통합 검색량 상대값 (0~100, 미사용)
├── shopping_click_absolute.csv              # 쇼핑 클릭 절댓값 (wide: 500키워드 × 1,420일)
├── shopping_click_trend.csv                 # 쇼핑 클릭 상대값 (0~100, 미사용)
├── gender_m.csv                             # 남성 클릭 ratio (wide)
├── gender_f.csv                             # 여성 클릭 ratio (wide)
├── gender_m_pct.csv                         # 남성 클릭 비율 % (wide)
├── gender_f_pct.csv                         # 여성 클릭 비율 % (wide)
├── age_10.csv ~ age_60.csv                  # 연령대별 클릭 ratio (wide, 6개)
├── age_10_pct.csv ~ age_60_pct.csv          # 연령대별 클릭 비율 % (wide, 6개)
└── sometrend_mention_long.csv               # SomeTrend 언급량 (long: 487키워드 × 1,543일 = 709,799행)
```

## configs/ — 설정 관리

YAML 파일로 모든 설정값을 중앙 관리한다.

### collection.yaml

```yaml
crawl:
  cid_1st: "50000006"          # 식품
  cid_2nd: "50000149"          # 과자/베이커리
  cat_1st_name: "식품"
  cat_2nd_name: "과자베이커리"
  start_date: "2022-01-01"
  end_date: "2026-03-01"
  window_months: 1
  pages: 25

select:
  final_n: 500
  min_appearance: 4
  seed: null
  strata:
    Q1_rare: 125
    Q2_low: 125
    Q3_mid: 125
    Q4_freq: 125

click_trend:
  api_url: "https://openapi.naver.com/v1/datalab/shopping/category/keywords"
  category: "50000149"
  start_date: "2022-01-01"
  end_date: "2026-02-28"
  time_unit: "date"
  sleep_seconds: 0.5
  input_csv: "keywords_selected_500_seed1527267025.csv"

search_trend:
  api_url: "https://openapi.naver.com/v1/datalab/search"
  start_date: "2022-01-01"
  end_date: "2026-02-28"
  time_unit: "date"
  sleep_seconds: 0.5
  input_csv: "keywords_selected_500_seed1527267025.csv"

click_gender:
  api_url: "https://openapi.naver.com/v1/datalab/shopping/category/keyword/gender"
  category: "50000149"
  start_date: "2022-01-01"
  end_date: "2026-02-28"
  time_unit: "date"
  sleep_seconds: 0.5
  input_csv: "keywords_selected_500_seed1527267025.csv"
  groups:
    - {code: "m", label: "m"}
    - {code: "f", label: "f"}

click_age:
  api_url: "https://openapi.naver.com/v1/datalab/shopping/category/keyword/age"
  category: "50000149"
  start_date: "2022-01-01"
  end_date: "2026-02-28"
  time_unit: "date"
  sleep_seconds: 0.5
  input_csv: "keywords_selected_500_seed1527267025.csv"
  groups:
    - {code: "10", label: "10"}
    - {code: "20", label: "20"}
    - {code: "30", label: "30"}
    - {code: "40", label: "40"}
    - {code: "50", label: "50"}
    - {code: "60", label: "60"}
```

코드에서는 `yaml.safe_load()`로 로딩

```python
PROJECT_ROOT = Path(__file__).resolve().parent.parent.parent
with open(PROJECT_ROOT / "configs" / "collection.yaml", encoding="utf-8") as f:
    _cfg = yaml.safe_load(f)["crawl"]
```

향후 `features.yaml`, `training.yaml`도 같은 패턴으로 추가

## 협업 규칙

### .gitignore 정책

```
data/          → 전체 제외, .gitkeep만 추적
outputs/       → 전체 제외, .gitkeep만 추적
.env           → API 키 보호
.venv/         → 가상환경
__pycache__/   → Python 캐시
```

### 의존성 관리

루트의 단일 `requirements.txt`로 전체 의존성을 관리한다. 스테이지별 requirements는 두지 않는다.

### 실행 방법

```bash
# 환경 설정
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium

# Stage 1: 키워드 수집
python pipeline/collection/crawl_keywords.py
python pipeline/collection/select_keywords.py
python pipeline/collection/crawl_shopping_click_trend.py
python pipeline/collection/crawl_search_trend.py
python pipeline/collection/crawl_shopping_click_gender.py
python pipeline/collection/crawl_shopping_click_age.py
python pipeline/collection/derive_gender_proportion.py
python pipeline/collection/derive_age_proportion.py
python pipeline/collection/estimate_shopping_click_absolute.py
python pipeline/collection/estimate_search_absolute.py

# Stage 3: 최종 데이터셋 생성 (51개 피처)
python pipeline/features/build_dataset_final.py
```
