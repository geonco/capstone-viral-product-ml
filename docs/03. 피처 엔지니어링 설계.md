# 03. 피처 엔지니어링 설계

## 3.1 피처 설계 원칙

모델에 입력되는 피처는 "이 키워드가 향후 14일 내 바이럴 될 조짐이 있는가?"를 판단할 수 있는 수치 정보여야 함.

**기본 설정:**
- 계산 기준: 예측 시점 t의 **최근 60일 window** (t-60 ~ t-1)
- 레이블 window: **향후 14일** (t ~ t+13)
- 데이터 소스: `search_absolute.csv`, `shopping_click_absolute.csv` (절댓값 사용)
- ε = 1e-6 (0 나누기 방지)

**피처 그룹 (Phase별):**

| Phase | 그룹 | 피처 수 | 상태 |
|-------|------|--------|------|
| Phase 1 | 검색량 기반 | 10개 | ✅ 구현 가능 |
| Phase 1 | 클릭수 기반 | 10개 | ✅ 구현 가능 |
| Phase 1 | 검색-클릭 결합 | 4개 | ✅ 구현 가능 |
| Phase 2 | SomeTrend 언급량 | 9개 | ⏳ 데이터 수신 대기 |
| Phase 2 | 검색-언급 결합 | 4개 | ⏳ 데이터 수신 대기 |
| Phase 3 | Demographic (성별·연령) | 14개 | ⏳ 데이터 수신 대기 |
| **합계** | | **51개** | |

상세 피처 목록 및 계산식: [피처_정의.md](./피처_정의.md)

## 3.2 검색량 기반 피처 (10개)

"이 키워드가 지금 얼마나 빠르게 뜨고 있는가"를 수치화.

### 멀티 윈도우 설계 원칙

3일, 7일, 14일 세 가지 시간 윈도우로 계산:

- **3일**: 초단기 급등 감지. 바이럴 시작 직후 가장 먼저 반응하는 신호.
- **7일**: 단기 추세. 요일 효과가 자연 상쇄되어 안정적인 단기 지표.
- **14일**: 중기 모멘텀. 일시적 스파이크인지 2주 이상 지속 추세인지 구분.

1\~2일 윈도우는 사용 안 함. 요일 효과(20\~30%)로 인해 실제 추세보다 요일 차이를 반영할 확률이 높음.

### 피처 목록

| Feature | 계산 방법 | 의미 | 목적 |
|---------|----------|------|------|
| `search_ma_7d` | mean(search[t-7:t-1]) | 최근 관심 수준 | 결합 피처 기준값 |
| `search_growth_3d` | mean(t-3:t-1) / (mean(t-6:t-4) + ε) − 1 | 초단기 급등 | peak 직전 패턴 |
| `search_growth_7d` | mean(t-7:t-1) / (mean(t-14:t-8) + ε) − 1 | 단기 증가율 | virality 강도 핵심 |
| `search_growth_14d` | mean(t-14:t-1) / (mean(t-28:t-15) + ε) − 1 | 중기 증가율 | 급등형 vs 완만형 구분 |
| `search_slope_7d` | linregress(search[t-7:t-1]).slope | 상승 속도 | viral momentum |
| `search_slope_14d` | linregress(search[t-14:t-1]).slope | 안정적 상승 추세 | 노이즈 제거 trend |
| `search_acceleration` | search_growth_7d − search_growth_14d | 상승 가속도 | 폭발 직전 탐지 |
| `search_std_7d` | std(search[t-7:t-1]) | 관심 변동성 | spike형 viral 탐지 |
| `search_pos_14d` | search[t-1] / (max(search[t-14:t-1]) + ε) | peak 근접도 | timing signal |
| `days_since_max_14d` | t-1 − argmax(search[t-14:t-1]) | peak 경과일 | peak timing 핵심 |

## 3.3 클릭수 기반 피처 (10개)

검색(관심)과 달리 클릭은 **실제 구매 행동**으로 이어지는 신호. 검색 증가 없이 클릭만 증가하는 패턴은 구매형 viral의 선행 신호.

| Feature | 계산 방법 | 의미 | 목적 |
|---------|----------|------|------|
| `click_ma_7d` | mean(click[t-7:t-1]) | 실제 행동 관심 수준 | virality 강도 핵심 |
| `click_growth_3d` | mean(t-3:t-1) / (mean(t-6:t-4) + ε) − 1 | 행동 급등 | 조기 viral signal |
| `click_growth_7d` | mean(t-7:t-1) / (mean(t-14:t-8) + ε) − 1 | 행동 관심 증가 속도 | 구매형 viral 탐지 |
| `click_growth_14d` | mean(t-14:t-1) / (mean(t-28:t-15) + ε) − 1 | 중기 행동 추세 | hype 지속성 판단 |
| `click_slope_7d` | linregress(click[t-7:t-1]).slope | 행동 상승 속도 | engagement strength |
| `click_slope_14d` | linregress(click[t-14:t-1]).slope | 안정적 행동 추세 | sustained interest |
| `click_acceleration` | click_growth_7d − click_growth_14d | 행동 가속도 | explosion signal |
| `click_std_7d` | std(click[t-7:t-1]) | 행동 변동성 | spike 탐지 |
| `click_pos_14d` | click[t-1] / (max(click[t-14:t-1]) + ε) | 행동 peak 근접도 | peak timing |
| `days_since_click_max_14d` | t-1 − argmax(click[t-14:t-1]) | 클릭 peak 경과일 | lifecycle 반영 |

## 3.4 검색-클릭 결합 피처 (4개)

두 신호의 **관계**에서 추가 정보를 추출. 검색은 많지만 클릭이 적으면 관심은 있으나 구매로 이어지지 않는 상태, 반대면 구매 의도가 높은 상태.

| Feature | 계산 방법 | 의미 | 목적 |
|---------|----------|------|------|
| `click_search_ratio` | click_ma_7d / (search_ma_7d + ε) | 검색 대비 행동 전환율 | real viral 가능성 |
| `click_lead_signal_7d` | click_growth_7d − search_growth_7d | 행동이 관심보다 앞서는 정도 | 구매형 viral 탐지 |
| `engagement_force` | click_ma_7d × search_slope_7d | 클릭 강도 × 검색 상승 모멘텀 | 복합 강도 예측인자 |
| `click_peak_gap` | click_pos_14d − search_pos_14d | 클릭 vs 검색 peak 위치 차이 | timing 구조 파악 |

## 3.9 NaN 처리 전략

1. **forward-fill**: 직전 유효값으로 대체 (일시적 데이터 누락 처리)
2. **backward-fill**: 최초 구간 NaN 처리
3. **0 대체**: 위 두 방법으로도 NaN이면 0 (데이터 없음 = 검색 없음으로 간주)
4. **샘플 제외**: 60일 window 내 유효값이 30일 미만이면 해당 (keyword, t) 샘플 제외
