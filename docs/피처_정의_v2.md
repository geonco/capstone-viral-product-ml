# 피처 정의 v2

## 개요

v1(`dataset_final.csv`, 51개 피처)에서 변화량 윈도우를 확장하고 품질 필터 기준을 강화한 버전.
출력 파일은 `data/processed/dataset_v2.csv`.

변수 정의는 다음과 같다. `t`는 예측 시점(예측 직전 마지막 날의 다음날 인덱스)이고, `s[i]`는 i번째 날의 검색량, `c[i]`는 클릭수, `m[i]`는 SomeTrend 언급량이다. lookback 배열 `X_lb`는 `X[t-60 : t]`로 길이 60의 배열이며, 인덱스 0이 가장 오래된 값, 인덱스 -1이 예측 직전(t-1)이다. `ε = 1e-6`은 0 나눗셈 방지용 상수다.

| 항목 | 내용 |
|------|------|
| **계산 윈도우** | 60일 lookback (t-60 ~ t-1 기준 계산) |
| **레이블 윈도우** | 14일 forward (t ~ t+13) |
| **데이터셋 기간** | 2022-05-01 ~ 2026-02-14 |
| **피처 수** | 107개 (search 27 + click 27 + 결합 6 + mention 27 + 결합 6 + demographic 14) |
| **레이블 수** | 3개 (virality_score, log_virality_score, peak_time) |
| **출력 샘플 수** | 628,643개 (제외: 62,971개) |
| **출력 파일 크기** | 약 1.1GB |

---

## 품질 필터 (v1 대비 변경)

v1은 원본 NaN 개수를 기준으로 샘플을 제외했다. v2는 fill_nan(ffill → bfill → 0 채움) 이후의 실제 값 기준으로 필터링한다.

필터 조건은 search 신호 기준으로, 60일 lookback의 **앞 30일(가장 오래된 절반)**이 모두 비활성이면 제외한다. 비활성이란 원본 raw 데이터 기준으로 결측값이거나 검색량이 0인 날을 의미한다. 수식으로 표현하면 `s_invalid[lb_s : lb_s+30].all()`이 True인 행은 제외한다. 여기서 `s_invalid = (s_raw.isna() | (s_raw == 0))`이다.

원본 결측값은 해당 날짜에 API에서 데이터가 수집되지 않았거나(수집 공백), 해당 키워드가 아직 존재하지 않았던 경우(예: 탕후루는 2022년에 사실상 검색량 없음)에 발생한다. fill_nan이 적용된 이후 배열이 아닌 원본 기준으로 체크하는 이유는, fill_nan의 bfill이 초기 결측 구간을 나중의 유효값으로 채워버려 실제로는 비활성 구간인데 필터를 통과하는 경우를 막기 위함이다.

## 변화량 피처 구조 (신호별 공통, 27개)

search, click, mention 세 신호 모두 동일한 구조로 27개 피처를 생성한다. 아래 설명에서 `X`는 세 신호 중 하나(search / click / mention)를 의미하며, `X_lb = X[t-60:t]`가 60일 lookback 배열이다.

### 이동평균 (5개)

`X_lb` 끝에서 n일을 잘라 평균을 계산한다. n = 3, 5, 7, 14, 30을 각각 계산한다. 예를 들어 `search_ma_7d`는 `mean(s_lb[-7:])`이다. 단기(3d, 5d)부터 중기(30d)까지 수준 자체의 변화를 파악하는 용도다.

v1 대비 3d, 5d, 14d, 30d가 새로 추가되었고 7d는 유지된다.

### 성장률 (5개)

직전 n일 평균과 그 이전 n일 평균의 비율에서 1을 뺀 값이다. `growth_nd = mean(X_lb[-n:]) / (mean(X_lb[-2n:-n]) + ε) - 1`. n = 3, 5, 7, 14, 30에 대해 계산한다.

양수면 최근이 이전보다 높은 수준임을 의미하고, 0이면 동일, 음수면 감소를 의미한다. 30d growth는 lookback 60일 전반부(oldest 30일)와 후반부(recent 30일)를 비교하므로 60일 전체를 활용한다.

v1 대비 5d, 30d가 신규 추가되었다.

### 기울기 (5개)

직전 n일 구간에 선형회귀를 적용해 기울기를 구한다. `slope_nd = polyfit(arange(n), X_lb[-n:], 1)[0]`. n = 3, 5, 7, 14, 30.

growth가 이전 구간과의 비교라면, slope는 최근 구간 내 추세 방향을 나타낸다. 양수면 상승 추세, 음수면 하락 추세다.

v1 대비 3d, 5d, 30d가 신규 추가되었다. mention에는 v1에 slope 피처가 없었으나 v2에서 신규 추가된다.

### 표준편차 (3개)

직전 7, 14, 30일의 표준편차다. `std_nd = std(X_lb[-n:])`. 변동성(노이즈 vs 급등) 파악 용도다.

v1 대비 14d, 30d가 신규 추가되었다.

### 현재값 위치 (3개)

직전 n일 최고점 대비 현재값의 상대적 위치다. `pos_nd = X_lb[-1] / (max(X_lb[-n:]) + ε)`. n = 7, 14, 30. 1.0이면 n일 최고점에 위치, 0에 가까울수록 최고점 대비 낮음을 의미한다.

v1 대비 7d, 30d가 신규 추가되었다.

### 최고점 경과일 (3개)

직전 n일 내 최고점이 나타난 이후 경과한 날 수다. `days_since_X_max_nd = (n-1) - argmax(X_lb[-n:])`. n = 7, 14, 30. 0이면 오늘(t-1)이 최고점임을 의미한다.

v1 대비 7d, 30d가 신규 추가되었다.

### 가속도 (3개)

growth 윈도우 간 차이로 변화의 가속/감속을 측정한다.

`X_accel_short = growth_3d - growth_7d`는 초단기(3일)와 단기(7일) 성장률 차이다. 양수면 3일이 7일보다 더 빠르게 성장 중으로, 매우 가파른 급등 초입을 포착한다.

`X_accel_mid = growth_7d - growth_14d`는 단기(7일)와 중기(14일) 차이다. v1의 `X_acceleration`에 해당하는 피처로 이름만 변경된다.

`X_accel_long = growth_14d - growth_30d`는 중기(14일)와 장기(30일) 차이다. 트렌드가 장기적으로 가속 중인지 감속 중인지를 나타낸다.

## 신호 간 결합 피처

### 검색+클릭 결합 (6개)

`click_search_ratio`는 `click_ma_7d / (search_ma_7d + ε)`이다. 검색량 대비 클릭수 비율로, 높을수록 검색이 실제 구매 행동으로 이어지는 전환 강도가 강함을 의미한다.

`click_lead_7d`는 `click_growth_7d - search_growth_7d`이다. `click_lead_30d`는 동일 계산을 30d 기준으로 적용한다. 양수면 클릭 성장이 검색 성장을 앞지르고 있어 구매 의도가 관심보다 먼저 급등하는 신호다. v1의 `click_lead_signal_7d`에 해당하며, v2에서 30d 버전이 추가된다.

`engage_force_7d`는 `click_ma_7d × search_slope_7d`이다. `engage_force_30d`는 30d 기준 동일 계산이다. 클릭 강도와 검색 상승 모멘텀을 결합한 복합 신호로, 둘 다 클 때만 큰 값을 가진다. v1의 `engagement_force`에 해당한다.

`click_peak_gap`은 `click_pos_14d - search_pos_14d`이다. 클릭과 검색이 각자의 14일 최고점 대비 어느 위치에 있는지의 차이다. 양수면 클릭이 검색보다 더 높은 위치에 있음을 의미한다.

### 언급+검색 결합 (6개)

`mention_search_ratio`는 `mention_ma_7d / (search_ma_7d + ε)`이다. 검색량 대비 SNS 언급 비율로, 높을수록 온라인 버즈가 검색 관심보다 강함을 의미한다.

`mention_lead_7d`는 `mention_growth_7d - search_growth_7d`이다. `mention_lead_30d`는 30d 기준 동일 계산이다. 양수면 SNS 버즈 성장이 검색 성장을 선행하는 신호로, 바이럴 초기 징후 포착에 유용하다. v1의 `lead_signal_7d`에 해당하며, v2에서 30d 버전이 추가된다.

`viral_force_7d`는 `mention_ma_7d × search_slope_7d`이다. `viral_force_30d`는 30d 기준 동일 계산이다. SNS 언급 강도와 검색 상승 모멘텀의 결합 신호다. v1의 `viral_force`에 해당한다.

`mention_peak_gap`은 `mention_pos_14d - search_pos_14d`이다. v1의 `peak_gap`에 해당하며 이름만 변경된다.

## Demographic 피처 (14개, v1과 동일)

소스는 `data/raw/gender_m_pct.csv`, `gender_f_pct.csv`, `age_10_pct.csv` ~ `age_60_pct.csv` (6개)이며, 모두 t-1 시점 단일 값을 직접 참조한다.

`male_click_ratio`, `female_click_ratio`는 각각 남성·여성 클릭 비율이다. `gender_click_skew`는 `|male - female|`로 성별 편중도다. `gender_click_shift_7d`는 `male_ratio[t-1] - male_ratio[t-7]`로 최근 7일간 성별 비율 변화다.

`age10_click_ratio` ~ `age50p_click_ratio`는 10대부터 50대+까지 연령대별 클릭 비율이다. 50대+는 50대와 60대 비율의 합이다. `young_click_ratio`는 10대+20대 합, `mid_click_ratio`는 30대+40대 합이다.

`core_age_click_ratio`는 5개 연령대 중 가장 높은 비율 연령대의 비율 값이다. `age_click_entropy`는 연령 분포의 엔트로피로, 높을수록 연령대가 고르게 분포함을 의미한다. `age_click_shift_7d`는 핵심 연령대(core_age 기준)의 7일 비율 변화다.

## 레이블 (3개)

`virality_score`는 `max(s[t:t+14]) / (mean(s_lb) + ε)`로 계산한다. 향후 14일 최대 검색량을 과거 60일 평균으로 나눈 실질 성장 배율이다. 1.0이면 현 수준 유지, 2.5 이상이면 바이럴 가능성 높음을 의미한다.

`log_virality_score`는 `log1p(virality_score)`이다. virality_score는 오른쪽 꼬리가 긴 분포를 가지는데, log1p 변환으로 분포를 압축하여 RMSE 기반 학습의 스케일을 안정화한다. 모델 학습 시 주 타겟으로 사용하며, 예측값에 `expm1`을 적용하면 원래 virality_score 스케일로 복원된다.

`peak_time`은 `argmax(s[t:t+14])`로, 향후 14일 중 최대 검색량이 발생하는 날(0~13)이다.

## v1 피처명 대응표

자주 참조되는 v1 피처명의 v2 대응을 서술한다.

v1의 `search_acceleration`은 v2에서 `search_accel_mid`로 이름이 바뀐다. 동일한 계산(`growth_7d - growth_14d`)이며, v2에서는 `search_accel_short`(3d vs 7d), `search_accel_long`(14d vs 30d)이 함께 추가된다.

v1의 `click_lead_signal_7d`는 v2에서 `click_lead_7d`로 이름이 짧아지며, 30d 버전인 `click_lead_30d`가 추가된다.

v1의 `engagement_force`는 v2에서 `engage_force_7d`로, `viral_force`는 `viral_force_7d`로 변경된다. 각각 30d 버전이 추가된다.

v1의 `peak_gap`은 v2에서 `mention_peak_gap`으로, `days_since_max_14d`는 `days_since_search_max_14d`로 이름이 구체화된다.

## 구현 참고사항

`ε (epsilon)`은 1e-6으로 0 나눗셈 방지용이다.

NaN 처리 순서는 forward-fill → backward-fill → 0이다.

60일 품질 필터는 search 신호 기준으로만 적용한다. `(s_lb != 0).sum() < 30`이면 해당 샘플을 제외한다.

30d growth는 `growth_30d = mean(X_lb[-30:]) / (mean(X_lb[:30]) + ε) - 1`로 lookback 60일 전체를 사용한다. 이 피처를 계산하려면 lookback 60일이 모두 필요하므로, LOOKBACK=60 설정이 필수다.

인코딩은 `utf-8-sig`(BOM 포함 UTF-8)이며, 출력 파일은 `data/processed/dataset_v2.csv`이다.
