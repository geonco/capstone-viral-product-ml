# 05. 평가 지표 및 데이터 파이프라인

## 5.1 타겟 변수 정의

본 프로젝트는 두 가지 타겟을 예측한다:

| 타겟 | 유형 | 의미 | 활용 |
|------|------|------|------|
| **virality_score** | 연속값 (회귀) | 향후 14일 내 얼마나 급등하는가 (성장 배율) | 메인 타겟 |
| **peak_time** | 연속값 (회귀, 0\~13) | 향후 14일 중 몇째 날에 피크가 오는가 | 보조 타겟 |

두 타겟은 동일한 피처를 사용하며, 모델 아키텍처도 동일하고 출력층의 타겟만 교체한다. LightGBM 기준 수십 초 × 2로 추가 비용이 거의 없다.

### 5.1.1 타겟 ①: virality_score

### 산출 공식

```python
# 특정 키워드의 t시점에서:
past60_mean = mean(search_absolute[t-60 : t-1])   # 과거 60일 평균
future14_max = max(search_absolute[t : t+13])      # 향후 14일 중 최대값

virality_score = future14_max / (past60_mean + ε)  # ε = 1e-6
```

### 학술적 근거

**virality_score 해석:**

- 분모: 과거 60일 평균 검색량 (피처 계산 기준선과 동일)
- 분자: 향후 14일 최대 검색량
- 값이 2.0이면 "과거 평균 대비 2배 급등"
- 필요 시 `log(virality_score + 1)` 변환으로 우측 치우침 완화 가능

### 산출 예시

| 키워드 | 과거 60일 평균 | 향후 14일 최대 | virality_score |
|--------|--------------|--------------|----------------|
| 약과 | 2,000 | 15,000 | 15000/2000 = **7.5** |
| 크로플 | 3,000 | 8,000 | 8000/3000 = **2.7** |
| 초코파이 | 10,000 | 11,000 | 11000/10000 = **1.1** |
| 현미 크래커 | 500 | 300 | 300/500 = **0.6** |

### 분류 변환 (참고용)

```python
viral_label = 1 if virality_score > 2.5 else 0
```

임계값에 따른 모델 성능 변화를 분석 포인트로 활용.

### 5.1.2 타겟 ②: peak_time

#### 산출 공식

```python
# 특정 키워드의 t시점에서:
peak_time = argmax(search_absolute[t : t+13])    # 0~13 (향후 14일 중 최대값 발생 인덱스)
```

향후 14일 시계열에서 최대값이 나타나는 위치(0-indexed)를 타겟으로 사용.

#### 왜 별도 타겟인가

virality_score는 "얼마나 급등하는가"를 알려주지만, "언제 급등하는가"는 알려주지 못한다. 동일한 virality_score = 3.8이라도 2일 후 피크 vs 12일 후 피크는 대응 전략이 완전히 다르다.

#### 산출 예시

| 키워드 | 향후 14일 시계열 (요약) | peak_time |
|--------|----------------------|-----------|
| 약과 | [2000, 4000, **15000**, 8000, ...] | **2** |
| 크로플 | [3000, 3200, 3500, 4000, 5000, 7000, **8000**, 6000, ...] | **6** |
| 초코파이 | [10000, **11000**, 10500, 9800, ...] | **1** |

#### peak_time 특성

- **범위**: 0\~13 (연속값으로 회귀 처리)
- **분포**: 바이럴 키워드는 초반(0\~5)에 피크 집중, 비바이럴 키워드는 분산됨
- **평가 지표**: MAE (예: MAE=2.1이면 "평균 2.1일 오차로 피크 시점 예측")
- **분류 변환**: `peak_time ≤ 4` → "즉시 대응 필요", `5\~9` → "약 1주 내", `10+` → "여유 있음"

#### 모델 학습 방식

virality_score와 동일한 피처, 동일한 모델 아키텍처를 사용하되 타겟만 교체:

```python
# LSTM — 마지막 Dense 출력만 다름

```

## 5.2 평가 지표 설계

### 회귀 모델 평가 (LightGBM Regressor, LSTM Regressor)

#### 주 지표: RMSE (Root Mean Squared Error)

```
RMSE = √( Σ(predicted_score - actual_score)² / n )
```

- 큰 오차에 높은 페널티 → virality_score 10인 키워드를 2로 예측하는 실수를 집중 포착
- 단독으로는 "이 값이 좋은 건가?" 직관적 판단 어려움 → 보조 지표와 함께 사용

#### 보조 지표 1: MAE (Mean Absolute Error)

```
MAE = Σ|predicted_score - actual_score| / n
```

- "평균적으로 virality_score를 얼마나 틀리는가"
- MAE = 0.8이면 "평균 0.8점 오차" — RMSE보다 직관적
- RMSE와 MAE의 차이가 크면 → 일부 극단적 오예측이 존재한다는 신호

#### 보조 지표 2: Top-K Precision (**발표용 킬러 지표**)

```
실제 virality_score 상위 10개 키워드 vs 모델 예측 상위 10개 키워드
겹치는 개수 / 10 = Top-10 Precision
```

- **발표 시 활용**: "모델이 추천한 바이럴 키워드 10개 중 7개가 실제로 바이럴 되었습니다" (Top-10 Precision = 70%)
- 심사위원에게 가장 직관적이고 임팩트 있는 지표
- Top-5, Top-10, Top-20으로 다양하게 측정 권장

#### 보조 지표 3: Spearman 순위 상관계수

```
ρ = 1 - (6 × Σd²) / (n × (n²-1))
  d = 예측 순위 - 실제 순위
```

- 예측한 순위와 실제 순위의 상관관계 (-1 \~ +1)
- 1에 가까울수록 순위 예측이 정확
- Top-K가 상위만 보는 반면, 이건 **전체 순위 정확도**

### 분류 변환 시 평가 (virality_score > 2.5 기준)

#### 주 지표: F1-Score

```
Precision = TP / (TP + FP)  → "바이럴이라고 한 것 중 실제 바이럴 비율"
Recall    = TP / (TP + FN)  → "실제 바이럴 중 모델이 잡은 비율"
F1        = 2 × (P × R) / (P + R)
```

**왜 Accuracy가 아닌 F1인가**: 바이럴 비율이 10%면, "전부 비바이럴"이라고 답해도 accuracy 90%. 무의미한 지표. F1은 precision과 recall의 균형을 봄.

#### 보조 지표: ROC-AUC

- 임계값(2.0)을 0\~∞로 변화시키면서 True Positive Rate vs False Positive Rate를 그린 곡선의 면적
- 0.5 = 랜덤, 1.0 = 완벽
- "어떤 임계값을 잡든 전반적으로 분류를 잘 하는가"를 종합 평가

### peak_time 평가

#### 주 지표: MAE (Mean Absolute Error)

```
MAE = Σ|predicted_day - actual_day| / n
```

- MAE = 3.2이면 "평균 3.2일 오차로 피크 시점 예측"
- 실용적으로 ±3일 이내면 충분히 유의미 (주간 단위 의사결정에 활용 가능)

#### 보조 지표: 구간 정확도

```python
# 피크 시점을 3구간으로 나눠서 분류 정확도 측정
bins = {
    "즉시(0~4일)":  peak_time <= 4,
    "중기(5~9일)":  5 <= peak_time <= 9,
    "후기(10~13일)": peak_time >= 10,
}
bin_accuracy = correct_bin_predictions / total
```

- 정확한 날짜를 맞히지 못해도 "어느 구간인가"를 맞히면 실용적 가치 있음
- 발표 시: "피크 시점의 구간을 78% 정확도로 예측" 같은 메시지 가능

### 평가 지표 요약표

| 태스크 | 타겟 | 주 지표 | 보조 지표 | 발표용 핵심 |
|--------|------|---------|-----------|------------|
| 회귀 (강도) | virality_score | RMSE | MAE, Spearman ρ | **Top-10 Precision** |
| 회귀 (시점) | peak_time | MAE | 구간 정확도 (3-bin) | **"평균 N일 오차로 피크 예측"** |
| 분류 | viral_label | F1-Score | ROC-AUC | P/R 트레이드오프 그래프 |

#### 2-B. 결측치 처리

#### 2-C. 정규화 관련 주의

- **네이버 DataLab 0\~100 값**: 조회 기간 내 상대값. **반드시 모든 키워드를 같은 기간으로 조회**
- **LightGBM**: 트리 기반이므로 피처 정규화 불필요
- **LSTM**: 모든 입력 피처를 정규화 필수 (Min-Max 또는 StandardScaler)
  - 정규화 기준(mean, std)은 **학습 데이터에서만 계산**하고 테스트 데이터에 동일 적용
  - 테스트 데이터 포함하여 정규화하면 → 데이터 누수(leakage)

### Stage 3: 피처 엔지니어링 + 타겟 생성

#### 3-A. 피처 생성

```python
# 각 (키워드, 날짜) 조합마다 계산 (Phase 1: search + click, 24개 피처)
for keyword in keywords:
    for t in date_range:
        search = search_absolute[keyword]
        click = click_absolute[keyword]
        ε = 1e-6

        # 검색량 피처 (10개)
        search_ma_7d = mean(search[t-7:t-1])
        search_growth_3d = mean(search[t-3:t-1]) / (mean(search[t-6:t-4]) + ε) - 1
        search_growth_7d = mean(search[t-7:t-1]) / (mean(search[t-14:t-8]) + ε) - 1
        search_growth_14d = mean(search[t-14:t-1]) / (mean(search[t-28:t-15]) + ε) - 1
        search_slope_7d = linregress(search[t-7:t-1]).slope
        search_slope_14d = linregress(search[t-14:t-1]).slope
        search_acceleration = search_growth_7d - search_growth_14d
        search_std_7d = std(search[t-7:t-1])
        search_pos_14d = search[t-1] / (max(search[t-14:t-1]) + ε)
        days_since_max_14d = (t-1) - argmax(search[t-14:t-1])

        # 클릭수 피처 (10개): 동일 구조, click 사용
        # click_ma_7d, click_growth_3d/7d/14d, click_slope_7d/14d,
        # click_acceleration, click_std_7d, click_pos_14d, days_since_click_max_14d

        # 결합 피처 (4개)
        click_search_ratio = click_ma_7d / (search_ma_7d + ε)
        click_lead_signal_7d = click_growth_7d - search_growth_7d
        engagement_force = click_ma_7d * search_slope_7d
        click_peak_gap = click_pos_14d - search_pos_14d
```

#### 3-B. 타겟 생성

```python
past60_mean = mean(search_absolute[t-60:t-1])
```

#### Rolling Window Validation

학습 데이터를 점점 늘려가면서 평가하는 시계열 전용 교차검증:

```
Fold 1: 학습 2022-05~2023-12 → 평가 2024-01~2024-03
Fold 2: 학습 2022-05~2024-03 → 평가 2024-04~2024-06
Fold 3: 학습 2022-05~2024-06 → 평가 2024-07~2024-09
Fold 4: 학습 2022-05~2024-09 → 평가 2024-10~2024-12
Fold 5: 학습 2022-05~2024-12 → 평가 2025-01~2025-02
```

각 fold의 성능 평균 ± 표준편차를 리포트. 일반적인 k-fold cross-validation은 시계열에서 데이터 누수를 일으키므로 사용 금지.

## 5.4 추론 파이프라인

학습 완료 후, 실제 사용 시:

```
[사용자] 키워드 입력: "약과"
              ↓
[1] 네이버 DataLab API 호출 → 최근 90일 검색 트렌드 수집 (무료)
[2] 썸트렌드 무료 티어 → 최근 블로그/뉴스 언급량·감성 수집 (무료)
[3] 날짜 정보 → 요일, 월, 공휴일 자동 계산
              ↓
[4] 피처 자동 계산 (velocity, acceleration, MA, sentiment 등)
              ↓
[5-A] LightGBM: 피처 51개 벡터 → virality_score + peak_time 예측
[5-B] LSTM: 60일 시계열 행렬 + 연관어 벡터 → virality_score + peak_time 예측
              ↓
[6] 결과 출력:
    "약과 — 상승 강도 4.2, 예상 피크 4일 후, 바이럴 가능성 높음 (즉시 대응 필요)"
```

### 추론 시 데이터 비용: 0원

| 소스 | 학습 시 | 추론 시 | 비용 |
|------|--------|--------|------|
| 네이버 DataLab API | 4년치 일별 조회 | 최근 90일 조회 | 무료 |
| 썸트렌드 | 프리미엄 1개월 (180,000원) | **무료 티어** (최근 1\~3개월) | 무료 |

Train-Serving Skew 방지: 학습 때부터 블로그+뉴스만 사용하여 무료 티어와 일관성 유지.

## 5.5 전체 파이프라인 흐름도

```
[Stage 1: 수집]
  쇼핑인사이트 Top500 (분기별) → 키워드 목록 300~500개 확정
  네이버 DataLab API (일별) → search_trend 시계열
  썸트렌드 프리미엄 Excel (일별) → mention, sentiment 시계열
  썸트렌드 연관어 분석 → 키워드별 연관어 30개 수집
  통계청 KOSIS + 한국은행 ECOS → 경제지표 (CPI, CSI)
                    ↓
[Stage 2: 전처리]
  (키워드, 날짜) 기준 Join → 결측치 처리 → 정합성 검증
  연관어 → TF-IDF + PCA → 키워드별 20차원 벡터 생성
  economic_indicators.csv 매핑 → 월별 경제지표 부착
                    ↓
[Stage 3: 피처/타겟 생성]
  LightGBM용: 파생 피처 51개 테이블 (Phase 1~3)
  LSTM용: 60일 × 10~15채널 시퀀스 + 정규화 + 연관어 벡터 20차원 concat
  타겟: virality_score (연속값) + peak_time (0~13일) + viral_label (이진)
                    ↓
[Stage 4: 학습/평가 분할]
  시간 기준 분할: 학습 → 검증 → 테스트
  Rolling Window Validation (5 fold)
                    ↓
[Stage 5: 모델 학습]
  Dummy Model + Linear Regression (베이스라인)
  LightGBM Regressor (메인 ①)
  LSTM Regressor (메인 ②)
  Weighted Average Ensemble (LightGBM + LSTM)
                    ↓
[Stage 6: 평가]
  virality_score: RMSE, MAE, Top-K Precision, Spearman ρ
  peak_timing: MAE, 구간 정확도 (3-bin)
  분류 변환: F1, ROC-AUC
  모델 간 비교표 + SHAP 설명
                    ↓
[추론 파이프라인]
  키워드 입력 → API 자동 호출 → 피처 자동 계산 → 모델 예측 → 결과 출력
```
