## 6.2 핵심 설계 결정 요약

### 왜 네이버 DataLab인가?
한국 검색 시장 점유율 64%, 2007년부터 일별 데이터, 무료 API. Google Trends(26%, 샘플링 편향), 카카오(3.4%, 트렌드 API 없음), 트위터(과거 데이터 없음) 대비 압도적 우위. → [상세: 02. 데이터 소스 조사 및 선정.md](./02.%20데이터%20소스%20조사%20및%20선정.md)

### 왜 썸트렌드를 추가하는가?
검색량만으로는 "왜 뜨는지"를 모름. 소셜 언급량이 검색량보다 **3\~7일 선행**하는 패턴이 학술적으로 확인됨. 언급량 기반 9개 + 결합 4개 = 13개 피처 추가 완료. → [상세: 03. 피처 엔지니어링 설계.md](./03.%20피처%20엔지니어링%20설계.md)

### 왜 virality_score (연속값, 비율 기반)인가?
이진 분류(바이럴/비바이럴)로 하면 클래스 불균형(5% vs 95%)이 심각. 연속값으로 바꾸면 모든 키워드가 고유 타겟을 가져 불균형 문제 소멸. `future14_max / past60_mean` 비율로 정의하여 "몇 배 올랐는가"를 직접 측정. Z-score 대비 직관적이고, 과거 60일 피처 window와 기준선이 일치. → [상세: 01. 프로젝트 개요 및 방향 결정.md](./01.%20프로젝트%20개요%20및%20방향%20결정.md)

### 왜 peak_time을 두 번째 타겟으로 추가하는가?
virality_score는 "얼마나 급등하는가"만 알려줄 뿐 "언제 급등하는가"는 모름. 동일한 score 3.8이라도 2일 후 피크 vs 12일 후 피크는 대응 전략이 완전히 다름. 향후 14일 window 내 argmax로 정의(0\~13). 동일 피처·동일 모델에서 타겟만 교체하므로 추가 비용은 학습 시간 × 2뿐. → [상세: 05. 평가 지표 및 데이터 파이프라인.md §5.1.2](./05.%20평가%20지표%20및%20데이터%20파이프라인.md)

### 왜 LightGBM인가?
직접 설계한 파생 피처 기반, 설명 가능(SHAP), 빠른 학습(수십 초, 노트북 CPU), 표 데이터에서 SOTA 수준. XGBoost 대비 대용량 데이터에서 더 빠르고 메모리 효율적. LSTM은 데이터 및 피처 확보 후 Phase 2에서 추가하여 "전통 ML vs 딥러닝 비교" 실험 예정. → [상세: 04. 모델 선택 및 비교 분석.md](./04.%20모델%20선택%20및%20비교%20분석.md)

### 왜 2022년부터인가?
COVID-19(2020\~2021)가 구조적 단절을 일으켜 pre-COVID 데이터가 현재 패턴과 불일치. 4년(2022\~현재)이면 바이럴 사례 40\~80개로 EPP ≥ 2.0 충족, 트렌드 사이클(6년) 대부분 커버. → [상세: 02. 데이터 소스 조사 및 선정.md §2.7](./02.%20데이터%20소스%20조사%20및%20선정.md)

### 왜 썸트렌드 언급량을 추가하는가?
검색량만으로는 "왜 뜨는지"를 모름. 소셜 언급량이 검색량보다 3\~7일 선행하는 패턴이 학술적으로 확인됨. 13개 피처 추가 완료. TF-IDF/PCA 연관어 벡터와 경제지표는 이번 프로젝트 범위에서 제외. → [상세: 03. 피처 엔지니어링 설계.md](./03.%20피처%20엔지니어링%20설계.md)

### 왜 컴퓨팅 비용이 거의 0원인가?
LightGBM은 노트북 CPU에서 수십 초 내 학습 완료. 약 70만 샘플 규모에서는 유료 클라우드가 불필요. Phase 2 LSTM 추가 시에도 Colab 무료 T4 GPU로 충분. → [상세: 04. 모델 선택 및 비교 분석.md §4.7](./04.%20모델%20선택%20및%20비교%20분석.md)

### 왜 블로그/뉴스 채널만 사용하는가?
학습(프리미엄)과 추론(무료 티어)의 데이터 일관성 유지(train-serving skew 방지). 무료 티어가 블로그/뉴스만 제공하므로, 학습도 동일 채널만 사용. 발표 데모 시 유료 의존 없이 작동하는 시스템 완성. → [상세: 02. 데이터 소스 조사 및 선정.md §2.5](./02.%20데이터%20소스%20조사%20및%20선정.md)

## 6.3 예상 결과물

### 1단계 (메인): 바이럴 강도 + 피크 시점 예측

```
입력: 키워드 ("약과")
출력:
  LightGBM: virality_score = 3.8, peak_time = 2일  →  "바이럴 가능성 높음, 즉시 대응 필요"

  SHAP 설명:
    search_growth_7d       = +1.1 기여
    click_lead_signal_7d   = +0.8 기여
    engagement_force       = +0.5 기여
    search_acceleration    = +0.4 기여

  피크 시점 구간: "즉시(0~4일)" / "중기(5~9일)" / "후기(10~13일)"
```

### 2단계 (보너스, 시간 여유 시): 검색 트렌드 곡선 예측

```
입력: 키워드 + 과거 60일 시계열
출력: 향후 14일 일별 검색 트렌드 예측 곡선
  → 피크 도달 예상 날짜 자동 추출
```

2단계는 시계열 예측 모델(LSTM Forecaster 또는 Prophet) 별도 구현 필요. 1단계가 확실히 완성된 후 추가.

## 6.4 참고 논문 및 자료

| 주제 | 자료 | 핵심 내용 |
|------|------|----------|
| 발표 킬러 | **Top-10 Precision** (바이럴 강도) + **"평균 N일 오차로 피크 예측"** (피크 시점) + SHAP 설명 + ML vs DL 비교 |
| 트리 vs 딥러닝 | Grinsztajn et al. (2022) — arXiv:2207.08815 | 표 데이터에서 트리 모델이 80%+ 경우 딥러닝과 동등 이상 |
| 바이럴 탐지 | "Measuring and Detecting Virality" (2023) — arXiv:2303.06120 | 바이럴 정량 정의: retweet/follower > 2.16 |
| 버스트 탐지 | Kleinberg (2002), Cornell | 비용함수 기반 자동 버스트 구간 탐지 |
| 커뮤니티 확산 | Weng, Menczer, Ahn (2013) — Nature Scientific Reports | "많은 커뮤니티에 퍼질수록 바이럴" |
| ViralBERT | Rameez et al. (2022) — ACM UMAP | BERT+감성+수치 피처 결합 바이럴 예측 |
| SHAP 해석 | Lundberg & Lee (2017) | 게임이론 기반 모델 설명 프레임워크 |
| COVID 소비 변화 | Scientific Reports (2024) | 2020년 구조적 변화점 확인, pre/post 데이터 혼합 경고 |
| 식품 트렌드 가속 | Nature (2024) | 트렌드 채택 주기 12년 → 6년 압축 |
| 희귀 이벤트 샘플 | PMC (2019) | EPP ≥ 23 권장, 최소 사례 수 가이드 |
| LSTM 원리 | Hochreiter & Schmidhuber (1997) | 망각/입력/출력 게이트, 셀 상태 도입 |
| LightGBM | Ke et al. (2017) — NeurIPS | Leaf-wise 트리 + GOSS 샘플링, XGBoost 대비 빠르고 메모리 효율적 |
| 데이터 누수 방지 | towardsdatascience — "Avoiding Data Leakage" | 시계열 train/test 분할, walk-forward validation |
| 클래스 불균형 | Frontiers in Data (2021) | 절대 희귀성이 상대 비율보다 중요 |
