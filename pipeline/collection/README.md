# 키워드 수집 파이프라인

## 개요

바이럴 예측 모델에 사용할 식품 > 과자/베이커리 키워드를 네이버 데이터랩 쇼핑인사이트에서 수집한다.
단일 기간의 Top 500은 스테디셀러에 편중되므로, 1개월 단위로 쪼개서 각각 수집하고
바이럴/비바이럴 키워드가 골고루 섞이도록 그룹별로 나눠 뽑는 방식으로 선정한다.

## 파일 구조

```
test/crawling/
├── crawl_keywords.py          # 1단계: 크롤링 → 윈도우별 CSV 저장
├── aggregate_keywords.py      # 2단계: CSV 검증 → 통합 → 그룹별 선정
├── run_all.sh                 # 배치 실행 (1단계 → 2단계)
├── naver_datalab_keywords.py  # (기존 레거시, 참고용)
├── naver_datalab_trend.py     # (기존, 검색 트렌드 API)
├── naver_datalab_trend_mid6.py
└── requirements.txt
```

## 실행 방법

```bash
# 전체 실행
./run_all.sh

# 또는 단계별 실행
python crawl_keywords.py       # 크롤링 (중단 시 재실행하면 이어서 진행)
python aggregate_keywords.py   # 검증 + 통합 + 선정
```

### CSV 네이밍 규칙

`kw_{1분류}_{2분류}_{라벨}_{시작YYYYMMDD}_{종료YYYYMMDD}.csv`

예: `kw_식품_과자베이커리_2022-01_20220101_20220131.csv`

### 윈도우별 CSV 컬럼

| 컬럼 | 설명 |
|------|------|
| rank | 해당 윈도우 내 순위 (1~500) |
| keyword | 키워드명 |
| window | 윈도우 라벨 (2022-01) |
| window_start | 시작일 (2022-01-01) |
| window_end | 종료일 (2022-01-31) |

### 최종 선정 CSV 컬럼

| 컬럼 | 설명 |
|------|------|
| keyword | 키워드명 |
| stratum | 어떤 사분위에서 뽑혔는지 (Q1_rare/Q2_low/Q3_mid/Q4_freq) |
| appearance | 출현 윈도우 수 (50개월 중 몇 번 Top 500에 등장했는지) |
| best_rank | 최고 순위 |
| rank_std | 순위 변동성 (표준편차) |
| first_seen | 첫 등장 윈도우 |
| last_seen | 마지막 등장 윈도우 |

## 왜 윈도우 방식인가

네이버 데이터랩 쇼핑인사이트는 조회 기간 내 누적 인기순으로 Top 500을 보여준다.
4년치를 한번에 조회하면 "옛날과자", "초콜릿" 같은 항상 인기 있는 키워드만 상위를 독점한다.

1개월 윈도우로 쪼개면:
- 2022년 1월의 Top 500, 2월의 Top 500, ... 각각 수집
- "두바이초콜릿"처럼 특정 시기에만 반짝 등장한 바이럴 키워드도 포착
- 50개 윈도우 통합 시 고유 키워드 **3,588개** 확보 (단일 기간 대비 7배)

## 왜 그룹별로 나눠 뽑는가

### 문제: 단순 상위 N개 = 스테디셀러만 뽑힘

출현 횟수 기준 상위 50개를 뽑으면 전부 appearance=50 (매달 등장하는 키워드).
바이럴 예측 모델에는 "바이럴 터진 키워드"와 "안 터진 키워드" 둘 다 필요하다.

### 근거

| 출처 | 내용 |
|------|------|
| Ribeiro & Moniz (2020) | 회귀 모델도 극단적인 값을 충분히 봐야 제대로 예측할 수 있다 |
| 역학 연구 관례 | 희귀 케이스 1 : 일반 3~4 비율로 뽑는 게 학습 효율이 가장 좋다 |
| Riley et al. (2019) | 데이터 행 수(50키워드×1200일=6만행)는 충분하지만, 그 안에 바이럴 사례가 얼마나 있느냐가 핵심 |
| 프로젝트 docs 02 | 바이럴 이벤트가 최소 40~80개는 있어야 모델이 학습 가능 (EPP ≥ 2.0) |

### 스테디셀러만으로 부족한 이유

120일 윈도우(90일 기준선 + 30일 예측)로 데이터를 구성하면 스테디셀러도 약간의 변동은 있다.
하지만 스파이크의 **크기**가 다르다:

```
스테디셀러 "옛날과자":  평소 ratio 60 → 명절 80  → Z ≈ 2
바이럴     "두바이초콜릿": 평소 ratio 5  → 터짐 100 → Z ≈ 15
```

스테디셀러만으로는 virality_score가 0~3 사이에 몰려서,
Z > 5 같은 폭발적 바이럴이 어떤 건지 모델이 한 번도 보지 못한 채 학습하게 된다.

## 그룹 분류 기준

3,588개 키워드 중 5개월 이상 등장한(90일 기준선 계산이 가능한) **1,104개**를 대상으로,
`appearance`(출현 윈도우 수)의 **사분위수(quartile)**로 4개 층을 나눈 뒤 층마다 정해진 수만큼 뽑는다.
분류 기준이 데이터에서 자동으로 결정되므로(`pd.qcut`) 임의 임계값이 필요 없다.

| 층 | 범위 (appearance) | 의미 | 후보 수 | 선정 |
|------|-------------------|------|--------|------|
| Q1_rare | 하위 25% | 거의 등장하지 않은 키워드 (바이럴 후보) | ~276개 | 13개 |
| Q2_low | 25~50% | 가끔 등장한 키워드 | ~276개 | 13개 |
| Q3_mid | 50~75% | 중간 빈도 키워드 | ~276개 | 12개 |
| Q4_freq | 상위 25% | 빈번하게 등장하는 스테디셀러 | ~276개 | 12개 |

희귀 층(Q1+Q2)에서 26개, 빈번 층(Q3+Q4)에서 24개로 약 **1:0.9** 비율.
희귀 출현 키워드에서 1개씩 더 뽑아 바이럴 패턴을 충분히 포함시켰다.

### 왜 사분위수인가

이전 방식은 `max_rank_jump >= 200`, `rank_std >= 100` 등 수작업 임계값으로 분류했다.
이 숫자들에 근거가 없어서 임계값을 바꾸면 결과가 흔들리는 문제가 있었다.
사분위수는 데이터 분포에서 경계를 자동으로 결정하므로 재현 가능하고 방어가 쉽다.

### 실제 데이터 분포 (크롤링 결과)

| 구간 | 키워드 수 | 예시 |
|------|----------|------|
| appearance 40~50 (매달 등장) | 166개 | 빼빼로, 페레로로쉐, 옛날과자 |
| appearance 20~39 | 216개 | 두바이초콜릿, 스웨디시젤리 |
| appearance 5~19 | 722개 | 먹태깡, 두바이쫀득쿠키 |
| appearance 1~4 (제외) | 2,484개 | 데이터가 1~4개월밖에 없어서 90일 기준선 계산 불가 |

```python
CID_1ST       = "50000006"       # 1분류 CID
CID_2ND       = "50000149"       # 2분류 CID
CAT_1ST_NAME  = "식품"

START_DATE    = date(2022, 1, 1)
END_DATE      = date(2026, 3, 1)
```

`aggregate_keywords.py` 상단에서 선정 수, 그룹별 배분 조정:

```python
FINAL_N        = 50
MIN_APPEARANCE = 5
STRATA_ALLOC   = {"Q1_rare": 13, "Q2_low": 13, "Q3_mid": 12, "Q4_freq": 12}
```

## 재실행 안전성

중간에 중단되더라도 재실행하면 남은 윈도우만 이어서 크롤링한다.

```python
existing = {f.name for f in OUTPUT_DIR.glob("kw_*.csv")}  # data/keyword_windows/
todo = [(s, e) for s, e in windows if csv_name(s, e) not in existing]
```
